# 간편 시작

서버 관리자와 사용자에게 필요한 준비를 나눴습니다. **사용자는 JSON 설정을 편집하거나 토큰을 복사하지 않습니다.** 현재는 초기 사용자 두 명 `alice`, `bob`을 생성하는 프로토타입입니다.

## 서버 관리자: 실행 후 파일 하나씩 전달

Docker Desktop/Engine과 Compose가 설치된 서버에서 프로그램 폴더를 준비합니다.

Windows에서는 **`서버-시작.cmd`를 더블클릭**합니다. 같은 작업을 명령으로 하려면 다음 한 줄입니다.

```powershell
docker compose up -d --build --wait
```

최초 자격증명과 사용자별 연결 파일을 자동 생성합니다. 다시 실행해도 기존 사용자 토큰과 DB를 초기화하지 않습니다. 서버에 Node.js, OpenCode, Claude Code는 설치하지 않습니다.

**서버 시작 파일은 호스트의 IP를 감지하고 공개 포트를 반영해 연결 파일의 주소를 자동으로 넣습니다.** 기본 포트는 3000이며 `.env`의 `PORT`를 바꾸면 새 포트가 반영됩니다. Windows는 `서버-시작.cmd`, Linux/macOS는 `sh 서버-시작.sh`를 사용합니다. 시작 파일은 LAN 접속을 위한 바인딩을 선택하되 명시한 `BIND_ADDRESS` 설정은 유지합니다.

회사 HTTPS 도메인이나 리버스 프록시를 사용하는 경우에만 실제 접속 주소를 `.env`에 명시합니다. 이 주소는 자동 감지보다 우선합니다.

```dotenv
QUEUE_SERVER_URL=https://queue.company.example
# 같은 서버의 HTTPS 프록시가 내부로 연결하는 구성이라면:
BIND_ADDRESS=127.0.0.1
```

회사 HTTPS 프록시/도메인 연결은 [서버 운영 안내](server.md#다른-pc에서-접속)를 따릅니다. 시작 파일은 최종 접속 주소를 표시하고 `.local/server-address.txt`에도 저장합니다. 재실행하면 기존 연결 파일의 주소를 갱신하면서 인증키는 유지합니다. 이미 다른 PC에 전달한 파일은 자동 수정할 수 없으므로, 주소가 바뀌면 새 파일을 전달해야 합니다.

직접 `docker compose up`만 실행하면 기본은 로컬 시험용 바인딩이며 `localhost:공개포트`가 발급됩니다. 이 모드에서는 다른 PC가 접속하지 못한다는 안내를 출력합니다. 컨테이너가 본 호스트와 사용자가 접속할 주소는 다를 수 있어 컨테이너 IP를 배포 주소로 사용하지 않습니다. 여러 NIC/VPN이 있으면 `QUEUE_HOST_ADDRESS` 또는 `QUEUE_SERVER_URL`로 올바른 주소를 지정할 수 있습니다. 방화벽·공유기 포트 전달·회사 DNS 설정은 별도이며 자동으로 변경하지 않습니다.

Linux에서도 보통 동일한 한 줄로 실행합니다. bootstrap이 프로그램 폴더 소유자를 기준으로 생성 파일의 소유자를 맞춥니다. 공유 디렉터리 등 특수한 권한 구성이면 `QUEUE_UID=$(id -u) QUEUE_GID=$(id -g) docker compose up -d --build --wait`처럼 명시할 수 있습니다. Node.js는 서버 컨테이너 안에서만 사용됩니다.

다음 두 파일이 생깁니다.

```text
.local/connections/alice.queue.json  → A에게 전달
.local/connections/bob.queue.json    → B에게 전달
```

각 사용자에게 **프로그램 폴더와 본인 연결 파일 하나**를 전달하면 됩니다. 프로그램 폴더는 저장소의 코드이며 서버의 `.local`, `.env`, node_modules, dist, DB를 함께 묶어 보내지 않습니다. 사용자는 GitHub 저장소에서 코드를 받거나 관리자가 준비한 ZIP으로 받을 수 있습니다. GitHub 저장소가 비공개이므로 직접 받으려면 해당 계정에 접근 권한이 있어야 합니다.

프로그램은 GitHub Actions의 성공한 `checks` 실행 아래 **Artifacts → mcp-queue-user**에서 ZIP으로 받을 수 있습니다. 이 압축본은 사용자 실행에 필요한 파일만 명시적으로 묶으며 서버의 접속 정보·DB·`.local`은 포함하지 않습니다. 관리자가 이 ZIP을 받아 전달하면 사용자마다 Git을 설치하거나 저장소 접근 권한을 받을 필요가 없습니다.

연결 파일은 사용자별 로그인·에이전트·관리자 토큰을 담은 **재사용 가능한 개인 접속 정보**입니다. 일회성 초대 링크가 아닙니다. 본인에게만 전달하고 공유 저장소에 넣지 마세요. 서버에 원래 사용자 토큰 묶음이 없으면 이 파일을 새로 만들 수 없으며, 기존 파일과 기존 수동 연결 방식은 그대로 사용할 수 있습니다.

## 사용자: 시작 파일 실행 후 화면에서 선택

PC에는 Node.js 22.16 이상과 본인이 쓰는 OpenCode 또는 Claude Code가 설치되어 있어야 합니다. 모델 로그인/API와 사내 문서 MCP는 평소 그 도구에서 사용할 수 있는 상태여야 합니다. 이 프로그램이 사내 서비스 계정이나 LLM을 새로 설치하지 않습니다.

Windows에서는 받은 프로그램 폴더의 **`사용자-시작.cmd`를 더블클릭**합니다. 최초 실행은 필요한 패키지를 설치·빌드하므로 사내 npm 레지스트리 또는 인터넷 접속이 필요합니다. 브라우저에 **내 PC 연결** 화면이 열립니다.

화면에서 다음만 진행합니다.

1. 관리자가 준 **본인 연결 파일**을 선택하고 **내 계정 연결**을 누릅니다.
2. **OpenCode / Claude Code** 중 하나를 선택합니다.
3. **평소 작업하는 프로젝트 폴더 주소**를 붙여넣고 **프로젝트 확인**을 누릅니다.
4. 기존에 쓰던 **문서 서비스**와 필요한 **검색·읽기 기능**을 선택합니다.
5. **연결하고 시작 → 내 요청함 열기**를 누릅니다.

도구 이름이나 JSON을 직접 작성하지 않습니다. 도구 목록은 실제 문서 MCP에서 읽으며 모델 호출은 하지 않습니다. 읽기 후보는 편의를 위한 추천입니다. 선택한 도구가 실제 읽기 기능인지 사용자가 확인해야 합니다.

OpenCode는 연결 프로그램이 전용 로컬 서버·포트·비밀번호와 `queue-reader` 설정을 자동 관리합니다. 4096 포트로 접속하거나 OpenCode 서버를 따로 켤 필요가 없습니다. 평소 사용하던 OpenCode 프로세스는 종료하지 않습니다. Claude Code는 로컬 CLI를 사용합니다.

Mac/Linux에서 시작 파일 대신 실행하려면 다음을 사용합니다.

```sh
npm ci
npm run build
npm run client
```

브라우저가 자동으로 열리지 않으면 터미널에 표시된 **PC 연결 주소**를 엽니다. 기본은 `http://127.0.0.1:3210`입니다. 이것은 PC 설정 화면이고 공통 업무 요청함은 중앙 서버 주소입니다. 설치를 자동으로 찾지 못하면 화면의 **설치를 찾지 못했을 때**에서 실행 파일 경로를 지정할 수 있습니다.

## 이후 사용

다음부터는 같은 시작 파일을 실행하고 **관리자 시작 → 내 요청함 열기**를 누르면 됩니다. 웹 요청함에서 받은 업무를 승인하고, 처리된 초안을 검토한 뒤 최종 전송합니다. 프로그램 창과 PC를 켜 두어야 업무를 처리합니다. PC 연결 창의 **중지**는 자신의 관리 프로그램과 프로그램이 띄운 전용 OpenCode 서버만 중지합니다.

웹 요청함에서도 연결 파일을 선택해 바로 로그인할 수 있습니다. 따라서 단순 요청 작성·조회만 하려면 PC 관리자를 실행할 필요가 없습니다. 다만 승인된 요청을 에이전트가 수행하려면 PC 관리자가 실행 중이어야 합니다.

## 자동으로 변경하는 것

- 개인 OpenCode/Claude Code 설정에 `queue` MCP를 추가합니다. OpenCode에는 문서 읽기용 `queue-reader`도 추가합니다.
- 기존 설정을 변경할 때 원본 옆에 `.mcp-queue-backup-…` 백업을 만들고 JSONC 주석과 다른 설정을 보존합니다.
- 프로젝트 저장소에 인증정보를 쓰지 않습니다. 사용자 홈의 `.mcp-queue` 아래에 연결·관리자 정보를 저장하고, OpenCode 전역 설정은 별도 개인 토큰 파일을 참조합니다. Claude Code의 Queue 토큰은 개인 Claude 설정에 저장합니다.
- Claude의 기존 user/project/local settings에서 모델·환경변수·apiKeyHelper를 읽어 수신 실행에 필요한 제공자 설정으로 사용합니다. 업무 hook·도구 권한을 그대로 복사하지 않습니다.

기업에서 별도의 전역 설정 디렉터리를 사용하면 XDG_CONFIG_HOME/CLAUDE_CONFIG_DIR을 따릅니다. 더 높은 우선순위의 프로젝트/회사 관리 설정이 `queue` 또는 `queue-reader`를 덮어쓰면 관리자와 설정 충돌을 확인해야 합니다. 회사 정책을 우회하지 않습니다.

전용 OpenCode 서버에는 선택한 Queue 설정과 읽기 프로필을 실행 시 다시 적용하고, 실제 읽기 프로필의 기본 거부 권한도 확인합니다. 기존 프로젝트 프로필이 수신 실행의 권한을 넓히지 않도록 하는 조치입니다. 회사가 관리하는 더 높은 우선순위의 권한 정책이 충돌하면 실행을 막고 확인을 요청합니다.

설정 화면은 로컬 PC에만 열고, 외부 Origin 및 다른 Host를 거절하며 API는 매 실행 생성한 연결 창 키를 요구합니다. 연결·모델·문서 인증정보를 중앙 서버로 업로드하지 않습니다. 중앙 서버에 전달되는 것은 해당 사용자 토큰으로 수행하는 요청 API 호출과 업무 결과입니다.

OAuth 전용 문서 서비스처럼 기존 클라이언트의 별도 인증 저장소가 필요한 구성은 자동 조회가 안 될 수 있습니다. 현재 자동 문서 조회는 Bearer/환경변수 기반 HTTP·SSE와 stdio를 지원합니다. 설치 안내로 실제 사내 인증·도구 호환성까지 보장되는 것은 아닙니다.

수동 연결이 필요한 환경에서는 [OpenCode 고급 설정](user.md)과 [Claude Code 고급 설정](claude-code.md)을 사용할 수 있습니다.
