자동 테스트는 사람용·에이전트용·관리자용 권한 분리, 미공개 초안 차단, 동일 키 재시도·내용 충돌, 인수 중복 차단, 오래된 실행 결과 거부, 알림 이전 승인 작업의 시작 시 확인을 검증합니다. 네트워크 오류를 초안 저장 전과 저장 후에 각각 주입해, 결과 재전송·재조회가 에이전트를 중복 호출하지 않는지도 확인합니다.

실제 두 물리 PC, 사내 HTTPS 프록시, GLM-5.3 사내 API, 문서 MCP, 해당 문서의 접근·공유 권한은 이 환경에서 검증하지 않았습니다. 사용자별 설정이 필요한 남은 연결 확인 범위입니다. 실제 OpenCode에 모델 프롬프트를 보내 답변을 생성하는 구간도 모의 통합 테스트로만 확인했으며, 사내 API의 토큰·RPM 사용량을 측정하지 않았습니다.

테스트 요청은 `[SMOKE]` 제목으로 남습니다. 테스트 스크립트는 서버 DB나 볼륨을 지우지 않습니다. 토큰·DB·UI 확인 스크린샷은 `.local` 아래에 두어 Git에서 제외했습니다.

## Claude Code 지원 추가 검증

2026-11-04 추가 변경에서 자동 테스트 17개가 통과했습니다. OpenCode 사용자와 Claude Code 사용자의 양방향 요청·승인·초안·검토 회신을 모의 런타임으로 확인했습니다. 실제 MCP 프로토콜로 문서 도구 프록시의 목록 필터와 허용되지 않은 직접 호출 거부를 검증했고, 별도 stdio 프록시 프로세스 → 모의 문서 MCP 연결도 확인했습니다.

Claude Code 2.1.318의 실제 `--help`로 사용하는 CLI 플래그 존재를 확인했습니다. 실제 Claude 모델 프롬프트·사내 API 인증·문서 서비스는 호출하지 않았습니다. 모의 CLI 테스트는 stdin 전달, 세션 ID 검사, 오류/빈 답변/권한 거부 처리, 프로세스 취소, 진단 문자열 비공개를 검증합니다. 회사 환경의 실제 추론까지 완료했다고 해석하면 안 됩니다.

## 간편 연결 화면 추가 검증

자동 테스트 20개가 통과했습니다. 초기 파일이 없는 상태의 bootstrap이 개인 연결 파일을 생성하고 재시작 시 토큰을 유지하는지 확인했습니다. 두 런타임의 연결 파일 확인 → 기존 문서 MCP 탐색 → 실제 MCP 도구 목록 조회 → 자동 등록·백업 → 관리자 시작 → 승인 작업 처리 → 중지·재시작을 모의 런타임으로 검증했습니다.

개인 설정의 JSONC 주석·기존 모델·다른 MCP 항목 보존, 다른 사용자 연결 파일로 바꿀 때 프로필 분리, 로컬 API의 창 키·Origin 검사도 확인했습니다. 문서 MCP는 실제 stdio 프로토콜을 사용한 모의 서비스이며 사내 문서를 읽지 않습니다. 브라우저에서는 연결 파일을 선택해 토큰 입력 없이 사용자 계정과 도구 선택 화면이 표시되는 것을 확인했습니다. 이 PC의 실제 에이전트 설정은 변경하지 않았습니다.

별도의 비어 있는 배포 디렉터리와 테스트 전용 Compose 프로젝트에서 사전 setup 없이 `docker compose up -d --build --wait`를 실행하여 초기 연결 파일 생성, 서비스 healthy, 연결 파일의 사용자 토큰 인증을 확인했습니다. 서비스에는 해시 파일 디렉터리만 마운트하며 원문 연결 파일은 마운트하지 않습니다. 이 검증에 사용한 별도 컨테이너·테스트 볼륨만 종료·정리했습니다.
